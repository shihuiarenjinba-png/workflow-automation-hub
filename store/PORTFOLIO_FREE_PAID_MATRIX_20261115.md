# Standard automation portfolio — Free / Paid launch matrix

Updated: 2026-11-15 JST

This document covers the four **standard** products only. It does not authorize Microsoft Store price changes, market changes, submission or publication.

| Product | Launch position | Why | Paid gate |
|---|---|---|---|
| Folder Automation Engine | **PAID — low-cost one-time candidate** | Clearest customer job, strongest safety evidence, consumer-first JP/EN flow, mature MSIX/Store provenance | Store-signed Private audience QA, final genuine screenshots, owner-approved price/markets/privacy/support |
| Scheduled API Runner | **FREE** | Stable CI but first success still depends on a saved JSON setup; API tools such as Postman/Bruno already have strong free entry points | In-app visual request/schedule builder, templates, clear secret handling, result history, first successful request in ~3 minutes |
| Browser Automation Runner | **FREE** | Strong free competitors; browser workflows can break when sites change; current advantage is simplicity/safety rather than breadth | JSON-free workflow authoring, selector/click target assistance, clear failure recovery/re-run, useful templates, materially easier UX than free competitors |
| Workflow Automation Hub | **FREE** | Current core is a narrow Blogger link-insertion workflow and OAuth onboarding still has friction | Guided OAuth with minimal outside setup, very clear rule creation, previewed affected-post counts, visible history/errors, demonstrated repeat usage |

## Portfolio rules

1. Free products must still be useful products, not intentionally crippled demos.
2. A product may be charged only when the UI exposes the core value without requiring developer documentation.
3. Japanese and English must describe the same function and the same safety boundary.
4. Side effects remain behind Preview / Dry Run plus explicit confirmation.
5. A paid product should target a first successful useful task within roughly three minutes for a new buyer.
6. Store price, markets, certification submission and Publish remain separate owner approvals.
7. A free product may later become a paid candidate only after its own paid gate is evidenced; CI success alone is insufficient.
8. The portfolio should compete on low friction, safety, predictable behavior and low one-time cost rather than matching enterprise suites feature-for-feature.

## Current portfolio role

- **Folder** — monetization lead product.
- **Scheduled API** — free acquisition / utility product.
- **Browser** — free acquisition / trust-building product.
- **Hub** — free niche utility / demand-validation product.

This matrix is an engineering/commercial recommendation for Store preparation. Actual Store pricing is intentionally not changed by this commit.
